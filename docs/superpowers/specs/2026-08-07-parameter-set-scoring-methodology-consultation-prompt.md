# 相談プロンプト: MPCパラメータセット比較のスコアリング手法(2026-08-07)

以下をそのまま外部AI(Gemini/Claude等)へ入力してください。

---

## 背景

自作レーシングカートのMPC制御で、25km/h走行時の蛇行(横方向振動)対策として3方向の
パラメータセット(S1: Q[e_y]/QN[e_y]低減、S2: wp_id_offset増加、S3: 終端コスト
QN再均衡)をdev3(3台構成シミュレーション)で同時比較検証した。各セットは別々の
車両(domain)に適用し、25km/h・アクチュエータ遅延70ms(予選環境較正値)・約30分間
走行させた。

**目的の締切**: 2026-08-21までにv_max=35km/hで蛇行のないスムーズな走行を実現する
必要があり、その前段階として25km/hでの有効な対策方向を特定したい。

## 実測データ

### ハード制約(30分間走行、基準=デフォルトパラメータ25km/h・36.6分走行の実測値)

| セット | 変更内容 | COLLISION-SUSPECTED | STUCK検知 | WALL衝突 |
|---|---|---|---|---|
| 基準(デフォルト) | Q[e_y]=200,000/QN[e_y]=1,000,000/wp_id_offset=1 | 18件(36.6分) | 5件(36.6分) | 0件 |
| S1 | Q[e_y]: 200,000→100,000 / QN[e_y]: 1,000,000→500,000 | 29件(30分) | 15件(30分) | 0件 |
| S2 | wp_id_offset: 1→2 | 9件(30分) | 7件(30分) | 0件 |
| S3 | QN[e_y]: 1,000,000→200,000 / QN[e_psi]: 1,000→100,000 | 12件(30分) | 4件(30分) | 0件 |

**S1はCLAUDE.mdの規律(ハード制約を先に適用し、悪化したセットはソフト指標に
関わらず不採用とする)により、この時点で既にFAIL判定としている。** S2・S3は
基準との差が指標によって分かれている(S2は衝突減少・STUCK増加、S3はほぼ同等)。

### 蛇行指標(参考、S1除外前の速度差分実験からの過去データ)

過去の速度差分実験(20km/h vs 25km/h、パラメータ変更なし)で、ekf_ey隣接差分の
標準偏差(サイクル単位の振動量)は以下の通り単調増加が確認されている:
- 20km/h: 直線11.02cm/cycle、コーナー15.21cm/cycle
- 25km/h: 直線20.06cm/cycle、コーナー21.63cm/cycle(20km/hの約1.8倍)

今回のS1/S2/S3実験でも同様の指標を算出可能(生ログの`[LOC-XCHECK]`行から
`ekf_ey`のサイクル間差分std)。

### その他、算出可能な指標

- `ekf_ey`の絶対値mean/p95(レースライン/コリドー中心からの乖離、
  「トラジェクトリのトレース率」の代理指標)
- ラップタイム(周回完了ログがあれば)
- ペナルティ相当イベント: ローカルdev3では実際の予選ペナルティ(CRASH/WALL/OVER
  →5km/h速度キャップ)が忠実に再現されているか未検証。WALL衝突件数と
  a_min/a_max(±1.37 m/s²)逸脱回数を代理指標として使う想定

## お願いしたいこと

**「目標とする走行を100点」としたスコアリング手法を設計してほしい。**
具体的には:

1. **ハード制約とソフト指標の混在をどう避けるか**: CLAUDE.mdの既存方針は
   「ハード制約(安全指標)を先に適用し、生存者だけをソフト指標(走行品質)で
   比較する」(2段階、点数を混ぜない)。この方針が今回のケースにも適切か、
   それとも単一の複合スコア(0-100点)にハード制約も含めて重み付けする方が
   良いのか、両方のメリット・デメリットを踏まえて推奨してほしい。

2. **「目標とする走行(100点)」の基準をどう定義するか**: 候補は
   (a) 本実験のデフォルトパラメータ25km/h実測値、(b) 蛇行が既知に少ない
   15km/h実測値、(c) 理論的な「蛇行ゼロ・完全追従」の理想値、のいずれか。
   それぞれのトレードオフを検討してほしい。

3. **各指標の重み付け**: 蛇行の小ささ・トラジェクトリ追従度・ラップタイムを
   どう配分するか(初期案: 50%/30%/20%)。締切(35km/h蛇行ゼロ)を踏まえ、
   蛇行指標を重視すべきか、それとも安全性(衝突・STUCK)寄りの重み付けが
   適切か。

4. **正規化方法**: 各指標(単位も範囲も異なる: 衝突件数[整数]、蛇行[cm/cycle
   またはcm/m]、乖離[m]、ラップタイム[秒])を0-100スケールへ変換する具体的な
   数式を提案してほしい(例: 相対悪化率ベース、シグモイド変換、ランク
   ベース等、それぞれの特性を踏まえて)。

5. **サンプルサイズの限界への対処**: 本実験はn=1(各セット1回、30分)であり、
   CLAUDE.md既存方針(n=1で確定しない、rule 1)に抵触する。スコアが僅差の
   場合にn=1のスコア差をどう解釈すべきか(例: 一定の閾値以下の差は「有意差
   なし」として扱う、等)の指針も欲しい。
