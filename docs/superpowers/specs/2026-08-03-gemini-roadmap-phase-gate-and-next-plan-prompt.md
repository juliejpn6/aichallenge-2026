# 見つかった重大な論点: Phase1ゲートは満たされているか

241節(2026-07-30、Phase1期間内)の実測: **v_max=15→20km/h(+33%)だけで直線蛇行stdが10.72°→20.22°(+89%、ほぼ倍増)という非線形悪化**が既に確認されている。これはロードマップのPhase1ゲート「20km/hでの振動悪化なし」を**満たしていない**ように読める。にもかかわらず、現在v_max=20km/hのままPhase1期間を運用してきており、Phase2(20→35km/hへの本格引き上げ)へこのまま進むべきかが不明確になっている。

241節自体も正直に「根本対処は限定的にのみ可能で、完全解決には構造的制約がある」「小さな一発の修正で解決する段階は既に過ぎている」と評価しており、未試行の根本対処候補5つを提示していた:
1. 大舵角ゲイン(0.67、実測済みだが未実装)の内部モデル化(難度中)
2. 明示的な無駄時間(dead-time)状態の追加(難度高、192節で一度却下済み)
3. 量子化された速度バケット型Q/Rスケジュール(難度低〜中、最も現実的と評価)
4. OSQPウォームスタートの履歴依存性検証(難度低)
5. 参照パス(x,y)自体のキンク補正(難度中)

また、249/250/253節のQ0(Q[e_y])スイープ実験は**1巡目・2巡目で傾向が完全に反転**し(コーナーでの「高Q0が良い」が逆転)、「Q0を確定的に選ぶのは時期尚早」という結論のまま、Q[e_y]=700,000は暫定採用されている。tau(actuator_lag_tau_s、現在190ms)も15km/h時代に確定した値で、20km/h環境での再検証はまだ行っていない。

ユーザーの直近の発言も共有する: 「T過剰応答[OT過渡応答]というやつですね。これをなんとかしないと35kmを達成できません」「15kmのときはtau=190で走行できていましたが、20kmのときはまだ変更したことがありません」— ユーザー自身もPhase1の蛇行対処と35km/h目標の関係を強く意識している。
