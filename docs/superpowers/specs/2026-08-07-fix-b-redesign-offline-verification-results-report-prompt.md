## 実装内容(ご提案通り)

```python
def _apply_overlap_floor(self, target_mag: float, corr_bound: float) -> float:
    if not self._ot_overlap_floor_enabled:
        return target_mag
    if self._ot_state != "OVERTAKING":
        self._ot_overlap_floor_mag = None
        return target_mag
    _before = target_mag
    self._ot_overlap_floor_mag = max(self._ot_overlap_floor_mag or 0.0, target_mag)
    floor = self._ot_overlap_floor_mag
    if np.isfinite(corr_bound) and corr_bound > 0.0:
        floor = min(floor, corr_bound - self._ot_overlap_corr_margin_m)
    target_mag = max(target_mag, floor)
    # (以下[OVERLAP-FLOOR]ログ、既存のエッジトリガー方式のまま無変更)
    return target_mag
```

STOPPING/proactive-bias分岐からの呼び出しは撤去(ご指摘通り、この分岐の
target_magはopp_lat_predを一切参照しないため保護不要と実コードで確認)。
`_update_overlap_state()`はdocstringに「Fix C専用として温存」と明記して

### フィクスチャ2: 0805-07慢性未達事例(wp62→118、41サンプル、8エピソード)

床が実際にtarget_magを持ち上げたのは5/41サイクル(最大持ち上げ量0.569m)。
平均達成率60.7%→65.0%。ただし2サンプルで達成率が100%を大きく超過:

| wp | offset(前) | min_needed | corr_bound | floor後 | 達成率(前→後) |
|---|---|---|---|---|---|
| 68 | 1.126 | 1.126 | 1.207 | 1.126 | 100.0%→100.0%(床のピークがここでセット) |
