# 背景(訂正のお知らせ)

前回相談(`2026-08-05-opp-lat-pred-collision-countermeasure-consultation-
prompt.md`)で提示した衝突事例について、**私(相談者側)の解釈に誤りが
あり、訂正します**。

前回、「`opp_wp`(対象車の最近傍waypointインデックス)がwp221印字時点の
230からwp227印字時点の238へ(Δ+8)変化した」ことを、あたかも1制御周期
(25ms)以内の変化であるかのように提示してしまいました。実際には
`[OT]`ログの出力間隔を直接測定したところ、**約1〜1.6秒に1回**(40Hz
制御周期のうち約40〜64周期に1回のみ)の間引きログでした。したがって
Δ+8(≈8m)の変化は約1.6秒間で起きたものであり、8m/1.6s≈5m/sという
相手の巡航速度(4.85〜5.49m/s)と自然に整合します。**物理的にあり得ない
速度ではなく、この件を根拠とした「waypointマッチングのアーティファクト
確定」という結論は前提が崩れています。**

一方、`opp_raw_lat_vel=3.691`という値自体は、コード内部の制御周期
(25ms)ごとの前回値との差分として毎周期計算されており、ログの印字
間引きとは独立しています。つまりこの数値自体は「その1周期で何かが
起きた」という実データですが、**その直前周期の`opp_wp`が実際いくつ
だったかは、現行の間引きログ(約1Hz)からは判別できません**。機構
(なぜ3.691が出たか)は依然として未解明です。

## 訂正後の状況整理

- 衝突事例そのもの(コリドーに5m超の空きがありながらoffsetが
  min_needed未達のまま振動→崩壊→衝突)という**現象自体は変わらず
  有効**です。
- `opp_raw_lat_vel=3.691`という異常値の**存在自体も生きています**
  (機構は不明でも、クランプ上限2.0を超える値が実際に記録された事実は
  変わりません)。
- ただし「waypointマッチングアーティファクトが原因」という**機構の
  特定は現時点で未確定に戻りました**。
