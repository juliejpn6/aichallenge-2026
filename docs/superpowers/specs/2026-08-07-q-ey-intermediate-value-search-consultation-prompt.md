# 相談プロンプト: Q[e_y]中間値探索とトレードオフの機構解明(2026-08-07)

以下をそのまま外部AI(Gemini/Claude等)へ入力してください。

---

## 背景

自作レーシングカートのMPC制御で、v_max=25km/hの蛇行対策としてQ[e_y]低減の
効果を同一セッション内対照(デフォルトQ[e_y]=200,000)付きで検証した
(Run 1、dev3、全domain v_max=25km/h・ay_max=7.0・delay=0.07・35分)。

## Run 1の結果(確定・再検討不要)

| domain | 設定 | ハード制約(対照比、ポアソン帯) | 蛇行(対照比、ブロックSE) |
|---|---|---|---|
| cand1再現 | Q[e_y]=100,000, QN[e_y]=1,000,000 | **FAIL**(衝突26/期待8/閾値13.66、STUCK27/期待6/閾値10.9) | 有意に改善(直線16.06 vs 26.57cm/m) |
| S1再現 | Q[e_y]=100,000, QN[e_y]=500,000 | **FAIL**(衝突36/期待8/閾値13.66、STUCK38/期待6/閾値10.9) | 有意に改善(直線14.90 vs 26.57cm/m) |
| 対照 | Q[e_y]=200,000(デフォルト) | — | — |

両者の差(QN比1M vs 500k)は蛇行・ハード制約ともに有意差なし——
**Q[e_y]=100,000そのものが「蛇行改善↔衝突・STUCK悪化」のトレードオフを
引き起こしている**ことが統計的に確定した(QN比は無関係)。

**判断方針(既存確定、CLAUDE.md §2 rule 4)**: ハード制約(安全指標)を
先に適用するため、Q[e_y]=100,000はこの結果単独では不採用。200,000
(悪化なし)と100,000(悪化あり)の間に、ハード制約を悪化させずに蛇行を
改善できる**中間値**が存在するかを次に探る。

## お願いしたいこと

1. **中間値の候補**: 200,000と100,000の間で、次に試すべきQ[e_y]候補値を
   提案してほしい(例: 140,000・160,000等)。対数的に絞るべきか、
   均等割りが良いか、根拠とともに示してほしい。
2. **トレードオフの機構仮説**: なぜQ[e_y]低減が衝突・STUCKを増やすのか、
   考えられるメカニズムを提示してほしい(例: コリドー追従の緩みで密集
   区間でのマージンが減る、追い越し判断への影響、等)。機構が分かれば、
   Q[e_y]以外の手当て(例: 密集区間限定でQ[e_y]を一時的に引き上げる
   スケジューリング)で問題を回避できる可能性もある。
3. **次の実験設計**: Run 1と同型(同一セッション内対照付き、dev3、
   v_max=25km/h・ay_max=7.0・delay=0.07)で、中間値をどう配置するか
   (例: d1=140k・d2=160k・d3=デフォルト対照、のような3点同時探索)を
   具体的な手順として提示してほしい。
4. **ハード制約のマージン**: 「対照と有意差なし」を合格ラインとするのか、
   それとも「対照よりわずかに改善」まで求めるのか、判定基準を確認したい。

- 次のdev3走行の具体的構成(domain割り当て・パラメータ値)
- ハード制約の合格ライン再確認
