# 報告プロンプト: Fix Bのcorr_bound無効タイムアウト実装+全OTエピソード横展開の結果

前回の相談(別Claudeのcorr_bound無効時の無期限床適用の指摘、Geminiの
「193%は例外か常態か横展開で確認すべき」という指摘)を踏まえ、両方を
実施しました。結果を報告します。

## 1. corr_bound無効タイムアウトの実装(別Claude提案)

既存の`unlock_inf_cycles`(H4-lite機構、80周期≈2秒)を流用し、
`_apply_overlap_floor()`にcorr_bound無効(負転落/非有限)が連続80周期を
超えたら床の適用自体を止める分岐を追加しました:

```python
_corr_valid = np.isfinite(corr_bound) and corr_bound > 0.0
if _corr_valid:
    floor = min(floor, corr_bound - self._ot_overlap_corr_margin_m)
    self._ot_overlap_floor_invalid_corr_count = 0
else:
    self._ot_overlap_floor_invalid_corr_count += 1
    if self._ot_overlap_floor_invalid_corr_count > self._unlock_after:
        return target_mag  # 床の適用を止め、既存機構(168節フリーズ等)へ委ねる
```

新規マジックナンバー0個、単体テスト9件追加、回帰スイート3211件PASS。
`[OVERLAP-FLOOR-TIMEOUT]`ワンショットログも追加しました。

## 2. 全OTエピソードへの横展開結果(Gemini提案)

利用可能な全ログ(2026-08-06のdev3セッション4本×3台=12ログ、qualifying
ログ0805-01〜07の7ログ)から`[OT] state=OVERTAKING`行を抽出し、
エピソード単位(side変化または10秒以上のギャップで区切る)でFix B
(タイムアウト込み)を反実仮想適用しました:

| 指標 | 値 |
|---|---|
| 総エピソード数 | 218 |
| 床が1回でも発動したエピソード | 83件(38.1%) |
| 総サンプル数 | 978 |
| 床が実際にtarget_magを持ち上げたサンプル | 185件(18.9%) |
| 達成率(Fix B前)平均 | 67.8% |
| 達成率(Fix B後)平均 | **83.7%** |
| 達成率>105%(過剰張り出し) | 129件(13.7%) |
| 達成率>150%(大幅過剰) | 48件(5.1%) |
| タイムアウト発動 | 7件のみ |

安全性の逸脱(コリドー突破、target_magがcorr_bound-marginを超える)は
0件でした(不変条件通り)。タイムアウトが7件のみだったことは、
corr_bound無効状態が通常は短時間(2秒未満)のアーティファクトである
という設計前提を裏付けています。

## 質問

1. 平均達成率67.8%→83.7%の改善、過剰張り出し13.7%(うち大幅過剰5.1%)
   という結果は、dev3ローカル検証(Phase 2)へ進むのに十分な材料と
   考えて良いか。
2. Gemini提案の「床の減衰(decay)機構」は、この結果を踏まえてもまだ
   不要と判断して良いか。過剰張り出しが13.7%(少数派だが無視できない
   頻度)という数字をどう評価すべきか——別Claude提案の「revisit
   trigger」(dev3実測でラップ影響+0.5秒超、またはコーナーでの床起因の
   大回りがライン逸脱指標に有意に出た場合に緩和策を実装)という基準を
   そのまま採用して良いか、それとも今回の横展開結果自体が既にトリガー
   条件を満たしていると考えるべきか。
3. dev3ローカル検証(Phase 2)を実施する場合、この横展開結果(達成率・
   過剰張り出し率・タイムアウト発動率)と比較すべき実測指標は何を
   優先すべきか(衝突/STUCK件数に加え、ラップタイム・コーナリング時の
   ライン逸脱等、レーシングロジックとしての質を測る指標を含めるべきか)。
