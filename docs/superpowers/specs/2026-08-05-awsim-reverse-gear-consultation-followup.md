# AWSIM自律モードREVERSEギア不受理問題 — 検証結果報告(第1回相談への回答)

前回相談(`2026-08-05-awsim-reverse-gear-consultation-prompt.md`)に対し、
Gemini・Claude双方から詳細な分析をいただいた。両者の最有力仮説を実装・
dev3実地検証したので、その結果を報告し、次の一手を相談したい。

## 実装した内容

両AIの分析(特にClaude側の「REVERSE要求中も運動指令が無いとAWSIMが自動的に
PARKへ戻している」という仮説)に基づき、以下を実装した。

1. **WAIT_PARK/WAIT_REVERSE中の加速度指令をゼロへ**: 従来はギア交渉フェーズ中も
   `hold_accel=-2.5`(能動的なブレーキ指令)を送り続けていたが、これを`acc=0.0`
   (真のアイドル、能動的な指令ゼロ)へ変更した。
2. **WAIT_REVERSEを行動ベース確認方式へ転換**: 従来は`GearReport==REVERSE`の
   確認を待つ間、速度指令をゼロ(`u=[0,0]`)に保持していた。これを、REVERSE要求と
   **同時に**後退運動指令(`backup_speed=-3.0`)を送り始めるよう変更した
   (確認を待たない)。成功シグナルを次の3種類に拡張した:
   - `GearReport==REVERSE`確認(従来通り)
   - **実速度が後退方向へ動き始めた**(`v <= -0.05 m/s`、新規)
   - タイムアウト(5秒、従来通り)

## dev3実地検証結果(run11)

上記実装後、dev3(3台自己対戦、d1=20/d2=17/d3=15km/h)で検証した。

- **`confirmed`(GearReport確認)**: 0件
- **`moving_backward`(速度フィードバックによる確認)**: **0件**
- **タイムアウト**: 19件(増加中)
- **衝突疑い**: 3台合計6件(各車2件ずつ)

## 新たに判明した、重要な追加事実

**REVERSE要求中、5秒間継続して`backup_speed=-3.0`(後退方向の速度指令)を
送り続けても、実速度フィードバックは一貫してほぼ完全なゼロのままだった**
(実測ログ: `v=-0.000`、`v=0.002`)。

これは前回相談時点では確認できていなかった新情報であり、以下の解釈上の
重要性を持つと考えている:

- 「シフト受理後に運動指令が無いから自動的にPARKへ戻る」という仮説(Claude案)は、
  今回**運動指令を最初から継続的に送っている**にもかかわらず改善しなかったため、
  単独では説明力が弱まったように見える。
- 一方で、「REVERSE自体がそもそも一切物理的に適用されていない(ギアが
  非REVERSE状態のままなので、速度指令自体を車両物理モデルが無視している)」
  という解釈がより有力に見える——ただし、これも確定ではない(例えば
  「一瞬だけ受理されるが、こちらの運動指令が実際にAWSIM側へ届く前に
  リバートしてしまう」というタイミング的な問題である可能性も排除できない)。

## 相談したいこと

1. 上記の新事実(継続的な運動指令があっても実速度が全く変化しない)を踏まえ、
   最有力仮説をどう更新すべきか。
2. 「一瞬だけ受理されるがすぐ戻る」という仮説が正しい場合、これをROS側の
   ログだけで検出する方法はあるか(例えば`GearReport`をより高頻度・低遅延で
   購読する、`rosbag`で生のDDSトラフィックを記録する等)。
3. 逆に、「REVERSEが一切適用されていない」という仮説が正しい場合、
   前回提案いただいた「最小再現ノード」(本線コントローラを完全に止め、
   素のrclpyスクリプトだけで静止→NEUTRAL→REVERSE+運動指令、を試す)を
   次に実施する価値が高いと考えているが、他に優先すべき切り分けはあるか。
4. 前回提案の「4条件マトリクス」(confirm待ち方式/指令同時送出方式 ×
   純ブレーキ併送/負速度指令併送)について、今回「指令同時送出+負速度指令」を
   既に実施し失敗したため、残る組み合わせ(特に「純ブレーキ相当の指令を
   併送しながらのシフト」)を試す優先度をどう考えるか。
