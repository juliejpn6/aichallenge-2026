# 前提(再検討不要、確定済みの記述)

- ロードマップ(`design_docs/roadmap_20260705_targets.html`)Phase1は08/26〜08/06(延長後)、出口ゲートは「主因特定+緩和策選定」(実装自体はPhase2)
- Part Cの高Q候補は、当初案の3M(208節時代)から**1.0M**へ改訂した(226-229節で3.0M→1.2M→0.8M→1.0Mへ既に調整済みの旧出発点であるため、229節で再現性最高と確定した1.0Mの方が現行tau=190ms確定後のシステムでの再検証対象として適切と判断)
- 分析ツール(`analyze_corner_ringing.py`)をC-0-3で拡張済み: wp269-282(236-240節の既知ホットスポット、S字コーナーでのSTUCK/巨大横偏差)を一般ringing分析から除外し専用の生データ分析(周回ごとの最大|ekf_ey|・stall発生率)を追加、Part Cの合否基準(一般ringing: 平均初期振幅<=6.0°かつ平均対数減衰率>=0.90、ホットスポット: stall_rate<=0%かつp95|ekf_ey|<1.5m)を事前に固定した(基準値は既存の19コーナー平均を参考にした暫定値)

# 実施方法

ローカル単体車両(`make dev`、対戦車なし)、`debug_extra_actuator_delay_s=0.055`で予選相当の実効遅延を注入(既存較正値、C-0-2で検証済み)。各条件6周走行後、`analyze_corner_ringing.py`で解析。n=1試行/条件(時間制約のため)。

# 実験結果

| Q\v_max | 20km/h | 15km/h |
|---|---|---|
| **700k(現行)** | C-1: **FAIL**(平均初期振幅8.27°/平均対数減衰率0.63/hotspot p95\|ekf_ey\|=1.53m) | C-3: **PASS**(振幅4.62°/減衰0.99/hotspot p95=0.58m) |
| **1.0M** | C-2: **FAIL**(振幅7.51°/減衰0.66/hotspot stall 1/6件・p95=2.17m) | C-4: **PASS**(振幅4.94°/減衰1.59/hotspot p95=0.49m) |

C-3・C-4はいずれも0クラッシュ・0ペナルティ、ラップタイムも83.5〜83.8秒台で非常に安定していた(result-summary.json実測)。C-2走行中、wp284近傍(ホットスポットのすぐ隣接区間)で速度が0.01-0.03m/sまで落ち込む近接停止が1回発生し、ローカルAWSIM環境固有の既知制約(REVERSE gearが実際には入らずBACKUPが空振り、PUSHで復帰)が観測された。

# 結論(現時点の私の見解)

**v_max=15km/hではQ[e_y]の値(700k/1.0Mどちら)に関わらず両基準PASS、v_max=20km/hではQ[e_y]の値に関わらず両基準FAIL**——極めてクリーンな2×2の結果であり、**蛇行の支配因子はv_maxであってQ[e_y]ではない**と判断しています。Q[e_y]を上げる効果は副次的(20km/hでは一般ringingをわずかに改善するがwp269-282ホットスポットを悪化させるトレードオフ、15km/hでは対数減衰率をさらに改善するが合否には無影響)。

作業仮説として、2つの効果の重畳を考えています:
1. 操舵アクチュエータの実遅延(tau≈190ms、固定)により、修正指令が効くまでに車が進む距離はv×tauで速度に比例して増える(15→20km/hで+33%)
2. コース曲率(kappa)は固定なので、同じコーナーを曲がるのに必要な横加速度はay=v²×kappaで速度の2乗に効く(15→20km/hで+78%)。241節実測の蛇行std悪化(+89%)に近い数字であり、②が悪化の主要因ではないかと推測している

この仮説自体は今回の実測から逆算した推論であり、専用の切り分け実験で直接検証したものではありません。

# 正直な限界

- 各条件n=1試行(6周)のみ。統計的有意性は未検証で、条件間の差が試行間ばらつきの範囲内である可能性を排除できていない
- C-2のwp284近接停止は、ローカルAWSIM環境固有の制約(REVERSE gear不調)が絡んでおり、Q[e_y]変更の純粋な効果と完全には切り分けられていない
- ロードマップに記載されていた「同一rosbagからのtau実測(FOPDTフィット、速度依存性の直接検証)」はまだ実施していない。今回のC-1〜C-4のログ・bagは手元にあるので、`analyze_actuator_delay.py`で速度別tau比較は追加実施可能

# 確認したいこと

1. **n=1試行の結論をどこまで信頼してよいか**: v_max=15km/hが両条件ともPASSした一方、20km/hが両条件ともFAILしたという「揃った」結果は、試行間ばらつきだけでは説明しにくいほど一貫していると考えていますが、緩和策の選定という重い意思決定の根拠にする前に、追試(せめてどちらかの条件をもう1回)をすべきか、それとも今回の結果で先に進んでよいか
2. **緩和策の優先順位の見直し**: 241節時点で挙がっていた5つの根本対処候補のうち、③(量子化された速度バケット型Q/Rスケジュール)は主にQの動的切替を想定したものでした。今回Qの効果が副次的と判明したことを踏まえると、③の優先度を下げ、①(大舵角ゲインの内部モデル化)・tau修正(②または新規のdelta_actual拡張)側に注力すべきという理解でよいか
3. **Phase1出口ゲートの達成判定**: 再定義したゲート「主因特定+緩和策選定」のうち、「主因特定」は今回の実測(v_max支配)で満たされたと考えてよいか。「緩和策選定」については、tau実測(未実施)を待たずに①(大舵角ゲイン内部モデル化)を選定候補として先に進めてよいか、それともtau実測の結果を見てから緩和策を確定すべきか
4. **残り約3日(〜08/06)の作業順**: (a)今回のC-1〜C-4のbag・ログを使ったtau実測(`analyze_actuator_delay.py`、速度依存性の直接検証)、(b)緩和策候補①の具体設計、(c)n=1試行への追試、のどれを優先すべきか
5. **Phase2戦略への影響**: v_maxが支配因子と分かったことで、Phase2(20→35km/h段階引き上げ)の段階幅・各段階のゲート判定(振動std基準)の設計自体に見直しが必要か。特に「ay=v²×kappaの2乗則」が正しければ、速度が上がるほど段階幅を狭める必要があるかもしれないという懸念がある
6. **総合判断**: 上記を踏まえた、Phase1残り期間(〜08/06)の具体的なタスク優先順位
