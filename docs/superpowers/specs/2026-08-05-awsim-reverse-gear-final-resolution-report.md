# AWSIM自律モードREVERSEギア問題 — 最終解決報告

これまで複数回相談させていただいたAWSIM自律モードでのREVERSE不受理問題が、
最終的に解決したので報告する。ご協力ありがとうございました。

## 最終的な根本原因

**AWSIM側は「ギア遷移が確定するまでの間に運動指令(非ゼロのspeed/acceleration)が
混ざっている」ことを事実上の拒否条件としている**(実車の「ブレーキを踏んでいないと
シフトできない」インターロックに近い挙動)。

## 決め手となった検証(第3回相談での指摘を受けて実施)

本線コントローラを完全停止した最小再現ノードで、以下2条件を分離して比較した:

**条件A(成功)**: 初期状態DRIVEから、
1. `GearCommand.NEUTRAL`要求を`acceleration=0.0`固定(運動指令なし)で送信
   → t=0.08sでNEUTRAL確認
2. Nのまま1秒保持(acceleration=0.0のまま)
3. `GearCommand.REVERSE`要求も`acceleration=0.0`固定のまま送信
   → **t=0.5sでREVERSE確認、以降5秒間安定して維持**(PARKへの逆戻りなし)

**条件B(失敗、以前の試験)**: REVERSE要求と`acceleration=-1.0`(後退駆動相当)を
**同時に**送信開始 → 1秒以内に強制的にPARK(22)へ戻り、以降10秒間REVERSEへ
復帰しなかった。

両条件の違いは「ギア遷移の要求と運動指令の開始タイミングが重なっているか、
遷移完了(確認)を待ってから運動指令を出しているか」のみであり、これが
PARKへの強制リセットの直接原因だった。

## 実装した修正

STUCK復帰状態機械のWAIT_REVERSE(REVERSE要求→確認待ちフェーズ)を、
「GearReport==REVERSEが確認できるまでは速度・加速度とも完全ゼロ
(`u=[0.0, 0.0]`、`acceleration=0.0`)で待機し、確認できて初めて後退運動指令
(`backup_speed`/`backup_accel`)を送り始める」という設計に統一した。
(中間ギアを`NEUTRAL`(公式仕様の値)にする修正は既に別途完了していた。)

## dev3実地検証結果(3台自己対戦、d1=20/d2=17/d3=15km/h)

修正後、REVERSE確認は**19/19件成功、タイムアウト0件**を記録した。実際の
後退運動も確認済み(実測例: v=-0.00→-0.07→-0.29→-0.51→-0.74 m/s、
dist=0.00→0.35m、明確な加速後退)。後退距離到達によるBACKUP完了(正常な
状態遷移)も複数回記録した。ローカル環境でここまで安定してREVERSEが機能した
のは、この調査全体を通じて初めてだった。

## 経緯のまとめ(遠回りした点も含めて記録)

1. 中間ギアに`PARK`(=22、非公式値)を使用していたバグを発見・`NEUTRAL`
   (=1、公式値)へ修正 → NEUTRAL確認は0%近辺→100%まで改善したが、
   REVERSE自体は改善しなかった。
2. 「確認を待たず同時に後退運動指令を送るべき」という仮説(外部AI複数名の
   分析に基づく)を一度実装したが、**これは逆効果だった**(まさに上記の
   拒否条件に抵触する変更だったため)。
3. 別の外部AIから「t=0の観測はManual操作の残存の可能性がある」
   「longitudinal.speedはAWSIM未使用」という重要な指摘を受け、本線コントローラを
   完全停止した最小再現ノードで因果分離試験を実施し、真因(運動指令と
   ギア遷移確定タイミングの重なり)を特定できた。
