# 背景

ROS2/Autoware自律走行レーシングカート(spatial MPC制御、40Hz制御ループ、
OSQP)で、コーナー出口のringing(蛇行)対策として「前方の曲率変動量(swing)
が大きいときにR[delta](操舵変化コスト)を動的に引き上げる」機構が実装
済み・本番投入中です(176節、以下「R-DELTA-SWING機構」)。

## 現状の実装

```python
# 毎制御周期、無条件に実行(OT/pit状態と無関係)
kappas_fwd = [reference_path.get_waypoint(wp_id + i).kappa
              for i in range(lookahead_wp + 1)]  # lookahead_wp=16(既定)
swing_raw = max(kappas_fwd) - min(kappas_fwd)
swing_ema = ema_alpha * swing_raw + (1 - ema_alpha) * swing_ema  # alpha=0.15

t = clamp((swing_ema - kappa_lo) / (kappa_hi - kappa_lo), 0.0, 1.0)  # kappa_lo=0.12, kappa_hi=0.30
smooth = t * t * (3 - 2 * t)  # smoothstep

R[delta] = R_base[delta] + boost * smooth  # R_base=500.0, boost=400.0(既定)
```

`swing`が`kappa_lo`未満なら`smooth=0`(ブーストなし)、`kappa_hi`以上なら
`smooth=1`(満額ブースト+400)、その間はsmoothstepで滑らかに補間されます。

## 問題

コース上に「wp340-40帯」と呼んでいる区間(周回境界をまたぐS字状の
方向転換区間、直線速度域で通過)があり、ユーザーの目視観察
(「WP340-40がもっともひどい」)と定量分析の両方で、既知の他ホットスポット
(wp196、wp269-282等)より**明確に悪い蛇行**が確認されています:

- 絶対偏差(周回内max|ekf_ey|): wp340-40帯で最大2.53m、他の帯は1.2m程度
- 周回間のばらつき(std): wp340-40帯で0.22〜0.55m、他の帯は0.02〜0.08m
  (=他の帯は「毎周ほぼ同じだけ寄る」系統的バイアス、wp340-40帯は
  「周回ごとに暴れ方が変わる」真の蛇行)
- ringingの対数減衰率が本間で極端に不安定: 同一config・同一地点(wp10)で
  ある本では0.035(ほぼ減衰しない持続振動)、別の本では0.956・1.040(健全)

## これまでの調査(過去節、否定済みの仮説)

同じwp340-40帯について、既に3つの仮説を実測データで否定しています:

1. **曲率SWING仮説(否定)**: wp340-40帯の17wp窓での曲率変動量(swing=0.23、
   total_var=0.32)は、既知ホットスポットwp269-282(swing=0.46、
   total_var=1.14)より明確に小さい。曲率の激しさそのものが原因という
   仮説は否定。
2. **レート飽和仮説(否定)**: `|dκ/ds|・v`のピーク値はwp340-40帯(0.19-0.21)
   の方がwp269-282(0.47)より低い。高速通過(wp340-40帯はv_mean 4.16-4.36
   m/s、他帯は2.00-3.72 m/s)という要因だけではレート飽和の深刻化を
   説明できない。
3. **ピットレーン切替の関与(否定)**: 周回境界と空間的に一致するピット
   レーン切替処理は、コード上レース開始直後の1回のみ実行され周回ごとの
   繰り返し観測とは構造的に無関係。

## 新しい発見(本日、`[R-DELTA-SWING]`ログの直接実測)

上記いずれの仮説も否定されたため、「R-DELTA-SWING機構自体がこの帯で
正しく効いているか」を、ローカル環境(dev3、3台)で診断ログを一時的に
有効化して直接実測しました(3台×複数周回、一貫した結果):

| wp帯 | ピークswing | ピーク時smooth(ブースト率) | ピーク時R[delta] |
|---|---|---|---|
| wp335-338(wp340-40帯の進入部) | 0.20〜0.24 | **44〜70%** | 668〜782 |
| wp341以降〜出口(wp0-45) | 0.02〜0.16 | 0〜15%(大半0%) | 500前後(ほぼブーストなし) |
| wp269-282(参考、既知ホットスポットだが減衰は健全) | 0.31〜0.32 | **100%**(kappa_hi=0.30突破) | 897〜898 |

wp269-282・wp340-40帯とも「曲率ピーク通過直後にブーストが急速に0%へ落ちる」
という点は共通していました。**違いはピーク自体の高さ**です: wp269-282は
ピークで`kappa_hi=0.30`を突破し満額ブースト(smooth=1.00)に達しますが、
wp340-40帯のピーク(swing=0.20〜0.24)はこの閾値に届かず、常に部分ブースト
(最大でも70%)止まりでした。

つまり、上記①で「swing絶対値自体はwp269-282より小さいので曲率SWING仮説は
否定される」と判断したその**同じ小ささが、smoothstepの閾値構造と
相互作用することで「ブースト量そのものの慢性的な不足」という形で
悪さをしている**可能性が浮上しています。

## このプロジェクトの制約・慎重に扱うべき理由

CLAUDE.md(自己更新ルール付きの索引ファイル)に、R[delta]/swing周りの
過去の調整履歴が確定済み結論として記録されています:

- `steer_low_pass_gain`を0.35から動かさない(強化・弱化どちらも悪化)
- `R[delta]`を500→1000へ一律に引き上げない(r_drateと併用で悪化)
- `steer_rate_max`を1.1→0.7へ絞らない(改善なし・直線std大幅悪化)
- R[delta]スイングブースト自体は複数回のクリーンA/B検証で
  「コーナー入口のピーキーさの主犯ではない」と無罪放免が出ている
  (ただし今回の論点=「特定区間でピークが閾値未達になる」は未検証)

つまりこの領域は「触ると高確率で悪化する」という苦い経験が蓄積している
領域であり、思いつきでのパラメータ変更は避けたいと考えています。

   妥当だと思いますか? それとも見落としている別の説明がありそうですか?

2. 対処法の候補として何が考えられますか? 例えば:

      でも満額ブーストへ届くようにする(ただし他の低swing区間への副作用
      = 過去に無罪放免が出た「コーナー入口のピーキーさ」を悪化させる

   b. 最低ブースト率(smoothの下限)を設ける(swing>0であれば常に一定割合
