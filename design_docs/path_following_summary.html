経路追従性の課題と対策まとめ

「レースラインを正確になぞる」ための課題・対処・結果と、残課題の整理。最終目標：最速ライン追従＋オーバーテイク経路の正確なトレース。

0. 背景：なぜ経路追従性か

レース戦略は先行時＝最速ラインを攻める／後追い時＝オーバーテイク経路を生成し実行の2局面。 どちらも「狙った線を正確に走れる」ことが前提。「経路追従性が高い＝速い」は正しく、二段構えで考える：

① ラインが最速（traj_mincurv）
最小曲率最適化ライン。今後さらに煮詰める対象。
② その線を正確になぞれる（追従）
生成ライン／オーバーテイク経路を誤差小さく追従。本書の主題。

1. 現在の状態（最新スナップショット）

安定周回
無衝突で複数周(5〜9周)
RMS e_y ≈ 0.4–0.57 m
真値(GNSS基準)の追従誤差
直線 std ≈ 1.1°
操舵の滑らかさ(発振なし)

採用中の設定：横目標＝レースライン（line_follow_w=1.0）、Q[e_y]=2e6、 GNSS軌跡方位の注入（方位バイアス補正）。 MPCの横目標 xr0 は直線で 0（＝レースライン, 壁中心ではない）＝目標は正しいことを確認済み。 残るズレは「目標の誤り」ではなく「執行（追従）の取りこぼし」。

2. 実施した対処と結果（課題→対処→結果）

課題対処結果状態
A. MPCがレースラインでなく壁コリドー中心を追従（常時0.5m級の横オフセット） 既存の lateral_blend/lateral_target 機構を再利用し、通常走行で横目標をレースライン(e_y=0)へ。line_follow_w 追加(可逆) 直線オフセット +0.55→+0.11m、ヘアピンの±2m振動を抑制、安定周回。目標が正しくなった 採用 (w=1.0)
B. 横追従の重み調整（ジッタ↔追従のトレードオフ） Q[e_y] を 6e5→5e6→2e6 で比較 5e6はジッタ増(std1.9°)。2e6が最良(std1.2°・追従良好) 採用 (2e6)
C. 方位バイアス（EKFヨーが実方位より約−1.5°。gyro積分のみで絶対補正なし） GNSS位置履歴から進行方位を求め、EKFのyaw観測として注入(yaw cov有限化＋速度ゲート)。imu_gnss_poser バイアス −1.5°→−0.17°(解消)。ただしRMS e_yは不変＝方位は見えていたズレの主因ではなかった 採用(保持)
D. ステアレート制約が固定Tsで過保守（空間MPCなのにΔs/vでない＝計画ターンインが鈍い、と仮説） 制約を物理的に正しい Δs/v ベースへ変更（試行） 発振・蛇行(直線std 1.17→3.45°)、2周で停止。
学び：固定Ts制約は“事実上のダンピング”だった		 巻き戻し
E. 追従精度を上げると発振する（安定性の天井） 方針A：操舵レートのソフトペナルティ r_drate(Δkappa²罰)で減衰を付与し天井を上げる アンダーステアで衝突(r_drate=50kで曲がり切れず外へ2.5m膨らみ)。
学び：減衰は必要なターンインまで鈍らせる		 撤去

補足：制御の操舵レートは「両側とも壁」だった

D と E の2失敗が動作点を挟み込んだ＝現安定点はこの制御構造のほぼ最良
  • ステアレートを緩める → 発振（課題D, run 211232）
  • ステアレートを締める/減衰 → アンダーステア（課題E, run 090143）
→ 現在の安定点（Ts基準ハード制限・R=[1e5,0]・ソフト罰なし）は、ノイズの多いEKF下でこの制御構造が出せる実用的な最良点に近い。 操舵レート系パラメータを片側に倒すと別の失敗が出るだけ。制御パラメータでこれ以上の追従改善は頭打ち＝残るレバーは制御の外（センシング/トラジェクトリ）。 ※（出力クリップ＝実アクチュエータ限界 rate·Ts は一貫して不変。Sim-to-Real整合を維持）

3. センシング（localization / EKF）の診断

GNSS pose ─► imu_gnss_poser ─► (位置cov 0.1 / 方位=GNSS軌跡方位を注入(対処C))
                                      │
wheel vx + gyro(wz) ─► gyro_odometer ─► (twist)
                                      ▼
                              ekf_localizer ─► /localization/kinematic_state（制御が使用）

EKF主要param：enable_yaw_bias_estimation:false / pose_additional_delay:0.14s / GNSS位置 ~20Hz。

診断項目内容状態
S1 方位バイアスgyro積分のみで絶対補正なし→約−1.5°。Q[e_psi]=1e8支配で操舵に直結対処C で解消
S2 位置のコーナー過小報告EKFがコーナーの横振れを約40-50%平滑化（過小報告）。真値RMS 0.55-0.58 に対しEKFは0.39しか見ない。 相互相関で時間遅れではなく振幅減衰と判明（EKFはむしろ60ms先行）→ pose_additional_delay調整では直らない未対処

GNSSは直線でEKFと一致(±0.07m)＝信頼可。コーナー差0.3mは本物のEKF過小報告。AWSIM真値poseは未記録(GTは衝突のみ)。

4. 残った課題の整理

最優先：追従精度の根治（最終目標に直結）

R1. コーナーで内側に切れ込み／膨らみ（真値 RMS 0.4–0.57m）
原因＝EKFのコーナー過小報告(S2)＋制御のターンインラグの二重。制御は誤差の約2/3しか見えず補正しきれない。 制御パラメータでは天井で詰められない（課題D/Eで実証）。レバーは下記2つ：
  • トラジェクトリ（ベストライン化）：第3コーナーの「左→右」キンク除去・レイトエイプックス化等。 低リスク 制御の天井に触れない・CSV編集で可逆・最終目標そのもの。推奨の次の一手。
  • センシング（EKF, S2）：コーナー過小報告・ノイズの低減。難 EKF本体はAutoware側で深掘りが必要。応答性を上げる前提条件。
R2. 第3コーナーの「左→右」（トラジェクトリのS字形状）
レースライン自体が手前で左へキンク(kappa+0.11)→右ヘアピン(−0.21)。車は忠実に左→右と操舵している＝追従は正しく、ライン形状の問題。 レイトエイプックス化（左キンク除去＋直線で左壁寄せ）で改善可。＝R1のトラジェクトリ対処と同じ作業。
R3. 第2コーナー脱出後の直線で中央へ垂れる（サグ +0.6m）
MPC目標はレースライン(0)で正しいが、脱出オーバーシュートが短い直線で戻り切らず中央寄りに。第3コーナー手前では回復。 ＝執行ラグ(S2＋制御)。R1と同根。

別系統：安定性・安全性（MPC監査の“静かなバグ”）

R4. 監査で見つけた未対処項目（挙動は出ていないが将来リスク）
  • ④ 例外捕捉バグ（except TypeError or ValueError＝TypeErrorしか捕捉せず）＋OSQP解ステータス未チェック
  • ⑤ infeasible判定が脆い（「全操舵が非ゼロか」）／⑥ 緩和で安全マージンを0まで削る
  • ⑧ 毎周期OSQPフルsetup（warm-start不使用）＝RT余裕／⑨ 経路マッチングが全点argmin＝ヘアピン誤マッチの恐れ
いずれも「静かに壊れる」型。レース投入前に押さえたいが、追従精度とは独立。
R5. Sim-to-Real / モデル忠実度
⑩すべり無視でay_max=12(>1G) ⑪ステアゲイン1.639の開ループ補正 ⑬粗いkappa/平滑化 ⑮出力ローパス無効 など。 実機レース・タイム詰めの段階で効く。

5. 今後の方針

STEP 1（推奨・次の一手） トラジェクトリのベストライン化（R1/R2/R3）。 第3コーナーのレイトエイプックス化から着手。低リスク・可逆・最終目標に直結。現行ラインと壁を可視化→修正案提示→確認の上で編集。
STEP 2 必要に応じセンシング(S2)の改善（EKFコーナー過小報告の低減）。追従の天井を上げ、より攻めたライン追従を可能に。
STEP 3 ライン追従が安定したらオーバーテイク経路の生成＋トレース（後追い戦略）。
STEP 4（並行） レース投入前にR4の安全系バグを整理。
総括： 横目標をレースラインへ正す（対処A, w=1.0）ことで「壁中心を走る」構造問題は解消し、目標は正しくなった。 方位も補正済(対処C)。残る追従誤差はEKFのコーナー過小報告(S2)＋制御ターンインラグで、 制御パラメータでは頭打ち（緩めると発振・締めるとアンダーステア）。 よって次は制御の外＝トラジェクトリのベストライン化（低リスク・最終目標直結）へ進むのが最善。
