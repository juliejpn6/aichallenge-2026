4. 技術Q&A(改善提案のための前提整理)

Q1. OSQPの問題規模と update() 化の書き換え範囲

問題規模(実測値・確定): N=20 / 状態 nx=3(e_y, e_psi, t) / 入力 nu=2(v, κ)。 変数 = nx(N+1)+nu·N = 103。制約行 = 等式63 + box103 + ステアレート19 = 185。

毎周期変化するもの(update()化の設計に直結):
要素毎周期変化?備考
x₀・上下限 l,u変化する初期状態固定・コリドー(ub/lb)は l,u 側に入る(A側ではない)・ay由来のvmax_dyn・P3のレート境界
線形制約行列 A の「値」変化するLTV線形化(A_lin/B_lin が wp毎の v_ref, κ_ref, Δs に依存)のため動力学ブロックの値は毎周期書き換え必須。ただし疎パターン(構造)は完全固定(3×3/3×2ブロックの位置は不変)→ OSQPの update(Ax=…) で対応可
コスト Pイベント時のみblockdiag(Q,QN,R)+2λSᵀS。Q切替(追い越し/ピット/将来のプリセット)時のみ update(Px=…)
コスト q変化する参照 xr(コリドー/ライン追従), ur(v_ref, κ_ref)
重要な実測: init 11.4ms の内訳は OSQP setup()自体は1.0msのみ、残り10.4msはPython側の疎行列構築(block_diag/kron/vstack/csc変換)。 つまり最大の勝ち筋は「setup→update」以上に「行列をパターン固定で事前確保し、毎周期は値配列(numpy)の書き込みだけにする」こと。 レート行列系は同手法でキャッシュ済み(実績あり)。マージン緩和リトライ(最大5回/solve)も現状は毎回フル再構築→同様に値更新化。

Q2. 車両の速度上限と高速域での操舵安定性

物理上限: 十分な余裕あり(いずれも実測)。
  • 他車実績: 予選のd2はcap 29.9〜30.1km/hを毎周安定維持(我々のマップ学習値)。最速チームtyuraは25km/hで全コーナーをノーブレーキ通過 → グリップ実力は ay≈20m/s²(我々のay_profile 2.6の約8倍)
  • 駆動系: AWSIMの加速度clamp ±1.37m/s²が実効制約。24km/hは到達に~5秒を要するだけで上限ではない
  • 結論: 24km/hは物理・グリップ両面で余裕内。制約は純粋に「操舵系の追従品質」と「制御周期の余裕」
高速域での操舵対策の見込み(正直な現状):
  • P3のΔκ境界は Δs/v_ref 基底なので速度に自動適応(高速ほどステップ実時間が縮み境界も縮む=構造的に破綻しにくい)
  • LPF(40Hz固定)の位相遅れは実時間一定 → 高速ほど距離換算の遅れが増える(24km/hで+13cm相当)。r_drateは速度非依存
  • 実績の空白: 現行の完成形(アンカー撤去後+offset=1)で検証済みなのは15km/hのみ。18〜22km/hの過去走行は旧構成。→ 残課題#2の段階検証(18→22→24を単独で、ステアstd/反転/clrを各段で判定)が必須であり、シミュレーション代替はしない方針

Q3. Qスケジュール化の紐付け方式(設計案)

採用予定の方式: 経路ロード時にwp毎の重みを曲率から事前計算(方式A)
  • キー: 各wpの|κ|(CSV由来・静的)。コーナーIDや区間テーブルは使わない(保守対象を増やさない)
  • 形: ブレンド w(κ)=clip(|κ|/κ_ref, 0, 1) で Q_straight ↔ Q_corner を連続補間し、Q_wp[i] を経路ロード時に配列化。P行列は kron(I,Q) をやめ per-step block_diag(これはQ1のupdate()化でP値の直接書込が可能になるため同時に安価に実現=#1と#4はセットで実装するのが正)
  • 速度依存: 毎周期の連続変化は不採用(QP地形の連続変形=振動源。アンカー項の教訓)。速度は v_max変更イベント時のプリセット切替(update_Q基盤が既存)のみ
  • ステア系重み: R[κ]=500(大きさ)とr_drate(Δκ)は当面グローバル維持。κスケジュールの主対象は Q[e_y]/Q[e_psi] の比(直線=ノイズを追わない緩さ / コーナー=チョード化を許さない締まり)

Q4. 相手車両の挙動モデルと予測精度

相手の性質: 予選・本戦とも各チームの自動運転スタック(固定アルゴリズム)。ブロックライン等の対抗AIは観測されていない(ルール上も防御的進路妨害は想定外)。実測でも周回再現性が高い:
  • d2: cap 29.9→30.1km/h(周回間ブレ±0.2km/h)/ d3: 15.2km/h固定。走行ライン(lat)も全周学習済み
  • 注意: 手動運転の相手(ローカルテスト)では反復前提が崩れる → lat学習は参考値(capはmax更新なので頑健)
減速ポイント予測の現状精度:
  • 位置分解能: wp=約1m + 包絡線平滑(k=5)で±2〜3m。速度精度: 周回間±0.2〜1km/h
  • ICC予測制動(実装済)は「先25mのmin」を取るため位置誤差±3mに頑健(用途に対して十分)
  • Stage2の攻めタイミング(仕掛け点の同定)には±2〜3mはやや粗い → 仕掛け窓の判定は「点」でなく「区間(相手が遅い区間に自分の完遂窓を重ねる)」で設計する方針。減速地点の同定精度を上げる場合は平滑kの縮小かa(s)=v·dv/dsのゼロ交差利用が候補
