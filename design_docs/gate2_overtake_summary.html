gate2「前方車の追い越し」課題 — 対応まとめ

自動運転AIチャレンジ2026 / Sim-to-Real SW部門 ・ MPC制御レーシングカート　|　ROS2 Humble + Autoware + AWSIM

1. 課題の概要

gate2 は安全ゲートの一つで、コース上に停車した他車3台（レースライン上に縦列）を、接触せず追い越して走行を継続する課題。 走行制御はデフォルトのMPC（OSQPベース、障害物回避コリドー）を使用する。

項目内容（実測・仕様より）
自車カート全長 200cm / 全幅 145cm（横半幅 0.725m） / ホイールベース 108.7cm
相手車(NPC)同型レーシングカート想定（横半幅 0.725m）・レースライン上に縦列で停車
配置（正しい接線基準 e_y: +左/−右）自車スタート e_y=+2.0（ラインの2m左）／相手 d2,d3,d4 = e_y≈+0.3、前方 ds=7,15,23m
幾何的要点左は壁が近く通れない。右側が開いているため「右へ寄って3台を追い越す」のが正解挙動
初期状態の問題：発進後そのまま前方車両に追突（追い越し挙動が一切成立しない）。回避部品は存在したが、前方車検知で「即停止（gate1挙動）」に固定されていた。

2. 結論（最終結果）

3台の追い越し成功
他車・壁への接触なし
追い越し後のライン復帰成功
第一コーナー通過成功
最高速度4.9 m/s

最終走行では、発進直後から右へ寄せ → 減速せず加速しながら3台を追い越し（e_y +2.0→−3.0）→ 戻りfunnelで滑らかにライン復帰（−3.0→−1.0）→ 第一コーナー通過、を達成した。

3. 診断と対策の経緯

走行ログ（rosbag/mcap）を毎回独自解析し、「症状 → 真因 → 対策 → 結果」を一段ずつ確定して進めた。重要な技術的教訓は最後にまとめる。

1追い越し判断ロジックの導入
症状
前方車を検知すると常に「停止（gate1挙動）」になり、追い越さない。
真因
前方車検知で use_obstacle_avoidance=False に倒し、直進＋減速停止に固定されていた。左右の空き判定・追い越し実行が無い。
対策
ステートマシン（NORMAL / OVERTAKING / STOPPING）を新設。前方車の符号付き左右位置と左右の空き幅を解析し、片側が空いていれば OVERTAKING、両側塞がりなら STOPPING（gate1保全）。ヒステリシスで状態のチャタリング防止。
結果
OVERTAKING には入るが、まだ追い越せない（次フェーズへ）。
2空き幅判定を実コース壁ベースへ（修正1）
症状
「右が空き」のはずなのに STOPPING に倒れ続ける。
真因
空き幅を 固定ボックス(max_width/2=3.0) で近似していた。実際の壁(片側6m以上)を見ておらず、空き幅を過小評価。
対策
各ウェイポイントが持つ実際の壁距離 wp.ub/wp.lb を用いて左右の空きを算出。
結果
右が空き(Rfree≈4.0)と正しく判定し OVERTAKING 発火。だが車体が右へ動かない（次フェーズ）。
3コリドーの「即右端」要求 → infeasible（funnel導入）
症状
前方車手前で急減速→停止→詰まる。「加速して抜ける」べき所でブレーキ。
真因
前方車が視界に入るとコリドー左境界が +1.8 → −1.7 へ一段でジャンプ。左寄りの自車はそこへ飛び移れず MPC infeasible → 安全STOP → ブレーキ。
対策
「徐々に右」funnel：コリドーを現在の自車位置から、先のウェイポイントへ向けて滑らかに遷移させる（近傍は自車を含むよう広げ、先で回避形状へ）。常に feasible を保つ。
結果
ブレーキ消滅。減速せず加速しながら右へ寄れるように。だが寄せ量が不足（次フェーズ）。
4発進直後の自己位置(ヨー)誤りによる左操舵ロス（修正B）
症状
発進直後にまず左へ操舵してしまい、貴重な接近距離を浪費。
真因
EKFの初期姿勢が yaw=0 / 共分散=100000（向き情報なし） で、発進後の動きから約3秒かけてヨーが収束。その間の誤ったヨーでMPCが誤操舵。
さらに根本は、起動シーケンスが /set_initial_pose をGNSS到着前に1回だけ呼び→失敗→スキップして発進していたこと。
対策
imu_gnss_poser の自動初期姿勢にレースライン向きを適用（try_apply_raceline_yaw）。GNSS到着時の最初の初期姿勢に正しい向き(~128°)が入り、起動タイミングに依存せず EKF が整列状態で開始。
結果
発進直後から正しく右へ操舵。左ロス解消。
5寄せ量不足 — 相手実寸とマージンの適正化＋crab前倒し
症状
右へ寄るが届かず、前方車にギリギリ接触。
真因
MPCは正しい右経路を計画しているが実行が後ろ倒し（受信ホライズンで先送り）。加えて 安全マージン1.63m が過保守で、クリアに e_y≤−1.8 が必要（出せるcrab約20°では届かない）。さらに 障害物半径0.5 は相手カートの実横半幅(0.725)を過小表現していた。
対策
① 相手半径 0.5→0.8（実寸是正＝接触防止）
② 追い越し時マージン 1.63→0.8（自車実footprintまで縮小。壁・相手共通。合計クリアランス1.6m＝安全最小）
③ Q[e_y] を 6e5→5e6 に前倒し（計画した右経路を早期実行）
④ 安全網：寄せ切れない時は実車位置基準で減速し接触を防ぐ
結果
3台の追い越しに成功（gate2クリア）。
6追い越し後のライン復帰（戻りfunnel・d_off調整）
症状
追い越し後にライン復帰できず、ゴールゲートの内側壁に接触。
真因
右へ寄せ過ぎ(e_y=−3.4)＋復帰機構が無く、ゴールゲートで内壁が迫って通常コリドー外＝infeasible → 内壁へ流れる。
対策
戻りfunnel：追い越し後にライン外なら、コリドーを現在位置からラインへ徐々に寄せて feasible に復帰。加えて d_off を 3.0 に調整（確実にクリアしつつ深入りしすぎない）。
結果
クリア後 e_y −3.0→−1.0 へ滑らかに復帰、内壁回避、第一コーナーも通過。

4. 最終解決策の構成（追い越しモード）

要素役割
ステートマシン（NORMAL/OVERTAKING/STOPPING）前方車の左右分布から「追い越す/止まる/通常走行」を毎周期判定。gate1（両側塞がり→停止）も保全。
実壁ベースの空き判定（修正1）固定ボックスでなく実際の壁距離で左右の空きを評価。
「徐々に右」funnelコリドーを現在位置から滑らかに遷移させ infeasible を回避（ブレーキ・詰まり防止）。
ヘディング前倒し（d_off / Q[e_y] / psi_bias）計画した右経路を早期に実行。MPCの支配項を右へ向ける。
実寸ベースのマージン（相手0.8 / 自車0.8）接触しない範囲で最大限寄せられるよう、過剰バッファを削り実寸を死守。
安全網（接触防止）寄せ切れない時は実車位置基準で減速・停止し、突っ込みを防止。
戻りfunnel追い越し後、ライン外から滑らかにレースラインへ復帰（内壁回避）。
初期姿勢ヨー補正（修正B）発進時のヨー誤りを解消し、発進直後から正しく操舵。

補足：判定はオドメトリ実測ベース、制御則はMPCに統一（別制御器を足さない）方針を維持。

7. 重要な技術的教訓

  • MPCは「参照ラインの向き」を非常に強く追従する（Q[e_psi]がQ[e_y]の約167倍）。進路を変えるにはソフトな目標でなく、参照経路/コリドーそのものを動かす必要がある。平行移動だけでは向きが変わらず無効。
  • コリドーは「即・最終形」でなく「徐々に」遷移させるとfeasibleを保て、ブレーキ・詰まり・infeasibleを防げる（funnel）。これは追い越しの「往き」と「戻り」の両方に有効。
  • マージンは相手・自車の実寸から設計する。障害物半径の過小表現や過剰な安全バッファは、接触または「寄せ切れない」の原因になる。安全最小＝自車半幅＋相手半幅＋小クリアランス。
  • 低速・発進時のlocalization（特にヨー）は不確実。制御の前提が崩れるため、起動時の姿勢初期化が極めて重要。
  • 分析の前提を疑う。参照CSVのpsi列が実進行方向と90°ずれていたことに途中で気づき、解析を是正した（コントローラ自体は座標から再計算しており正常だった）。
  • 「決定層」と「実行層」を分ける：判定（どちらへ・可否）は実測ベースの軽い解析、実行（経路追従）はMPC、安全網は最後の砦、という役割分担が堅実。

8. 今後（レース本番＝動く相手）に向けて

本対応は停車した相手に対する追い越しを確立した。動く相手＋予測が必要な本番に向けては、次の発展が望ましい：

  • 相手を「点群」でなく「車両ごとの位置＋速度」で扱う（現状はV2X予測サンプルを点として扱っており、動く相手で占有帯が膨張するため）。
  • 時空間での追い越し可否判定：自車と相手の数秒先を予測し、抜け切れるかを判定してからアグレッシブに踏み込む／不可なら追従・断念。
  • 本番では「速度優位の確保」と「横移動の完了可否」を協調制御し、安全網（接触回避）を常時併用する。
