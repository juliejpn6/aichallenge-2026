4. やろうと思ったがうまくいっていないこと(切り分け済み)

「init削減 → 予選欠落の根治」は不成立だった。ただし切り分けは完了:
検証結果含意
/clockの健全性(シム側)200Hz・欠落0回・max40ms・実時間係数1.000シミュレータのフレーム落ちではない
欠落とフェーズの相関交通中114回/分 vs クリーン86回/分交通処理は増悪要因だが主因ではない(クリーンでも高頻度)
tick充足率18,545/19,371 = 95.7%(4.3%のtickを取りこぼし)コントローラ側で毎秒約1.7回、25ms予算を超過する処理が発生
initとの関係init 11.4→5.2msでも欠落100→105回/分スパイク源はget_control(init+solve)の外=未計測領域にある
容疑者(毎秒〜1.7回・25ms超のスパイク源候補): ①PythonのGC(疎行列は撤廃済みだが他のnumpy一時配列・v2x/コリドー処理) ②OPP_MAPフラット配列publish(1Hz・350wp×2台) ③RViz予測マーカ等のpublish群 ④1Hzの[OT]ログprint/flush。次の一手はコールバック全体の区間計装で犯人を実測特定すること(推測で対策しない)。
