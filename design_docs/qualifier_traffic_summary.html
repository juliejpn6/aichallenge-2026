0. 前提: ルール変更と上位チーム分析

項目内容
環境変更予選から「衝突なし → 衝突あり(他車と同時走行)」に変更。
公式ペナルティCRASH(車両接触=前車リア×後車フロント): 10秒間5km/h上限 / WALL(壁・コースアウト): 5秒間5km/h / OVER(加速度±3m/s²超 or 250Hz以上publish): 2秒間5km/h。AWSIMは加速度入力を±1.37でclamp。
上位チームAutomitsu 46.0s / iASL(2位) 46.3s / B-CORE(1位) 48.8s。1位が最速でない=ペナルティ回避(安定完走)がスコアの本体。iASLは当チームと同一MPCコード(パラメータ違い)。
方針ペナルティ回避 ≫ 純ペース。まず v_max=15km/h で確実周回の土台を作り、対他車制御を仕上げてから速度を上げる。

1. 基盤: ペナルティ適合と計算負荷(07-02)

課題対処結果
指令加速度が a_max=3.2 でOVER違反(±3超)を誘発。a_min=−3.0は違反境界ちょうど。しかもAWSIMは±1.37でclampするため1.37超は無意味。 a_min/a_max = ±1.37(有効最大かつ違反マージン1.63確保)。 OVER違反 0件(以後全ラン)。
他車の予測円が1台=20個(MPC N点分)投入され、MPCコストが2倍(12.6→28ms)→制御22Hz→ステア暴れ→壁衝突→59%クロールで完走不能(0701予選ラン)。 n_pred_samples: 6(予測円を1台6個に間引き。0.5s掃引の被覆は維持)。後にrebuild_deadband: 0.3m(障害物が0.3m動いた時だけ占有マップ再描画)を追加。 制御 22→40Hz回復。MPC init+solve 42.8→18.1ms。
他車が占有格子の端にいると add_obstacles が IndexError → 制御ノード即死(0702予選ランで2回、以後クロール)。 map.py の円描画をグリッド境界でクリップ(端以外は挙動完全同一)。 IndexError 0(以後全ラン)。
確実に周回できる速度域が未確立。 v_max: 15km/h全域制限(実効=min(区間ref_vel, v_max, 曲率上限))。ay_max=5.5。 最急コーナー(半径2.6m)でも横G余裕44%。

2. 操舵チューニング: 15km/hでも曲がれない→安定ベースライン(07-02)

課題対処結果
15km/hでも最急コーナー(s≈250-270)で+3.7m膨らみ壁衝突。指令舵31°に実舵21°しか追従せず(turn-in不足)。 第1バッチ: steer_rate_max 0.35→1.5 + R[delta] 0→500(振動抑制の相方) + delta_max 32→45 + use_max_kappa_pred false(曲率スパイク対策) + Q[e_y]を検証済み2e6へ。 2周完走(初)。crashコーナー通過。
steer_rate 2.0 に上げたらステア震え(符号反転14.3回/s)+同コーナーで再crash。 PlanB: steer_rate 1.5 + steer_low_pass_gain 0.5(出力平滑) + Q=[3e6,6e7,2e6](ヘディング支配50→20倍)。 コーナー震え半減(6.9回/s)。ただし3周目に技術コーナーでcrash。
内側切り込み(コーナー93%イン)・直線逸脱の根治を狙い Q[e_psi] をさらに検証。 PlanC: Q[e_psi] 6e7→4e7(単独変数で検証)。 3〜4周無衝突を2回再現(81.1s/周±0.2)=安定ベースライン確立。※内側切込・直線逸脱はQが原因でないと判明(反証)。
AWSIMステアアクチュエータの実測限界: むだ時間200ms・レート109°/s・大舵角ゲイン0.67。raw1.5(=タイヤ141°/s)は実現不能な計画→スナップ振動の一因。 steer_rate_max 1.5→1.1(109°/s÷gain1.639に整合。「実機ができることだけを計画」)。 ステア1step振幅 0.90→0.37°。最大跳び19.8→6.7°。

3. 対他車制御: 追従(ICC)・追い越し・守り(07-03〜04)

3-1. 追従(ICC=インテリジェントクルーズコントロール)

課題対処結果
周回遅れ車に追突(最終ラップに集中)。旧ロジックは前方車を「静止物」扱いで距離だけ見ており、速度差(接近率)を考慮しない。 ICC化: v_safe=√(v_fwd²+2a(gap−margin))。相手速度まで減速して追従。margin=3.0m・検知20m(〜21km/hまで停車車に停止可)。 追従車間が中央値4.0m・90%が2-4m帯に収束、追従中速度std 1.4km/h(教科書的ACC)。
相手速度の生値に27.7km/hのスパイク(2フレーム差分)。 トラッカー平滑窓 2→6フレーム(端点差分)。 スパイク17.7km/hに抑制、std4.5→1.9。
ライン外の低速車に全速追突(検知帯±1.5mが参照ライン基準のため、帯外の車を無視。d=1.0m前方で v_safe=None・全速4.17m/s)。接触4件、全て車体横間隔1.15-1.47m<カート幅。 F1: 近距離(6m内)は「参照帯」でなく「自車との実横間隔<1.8m」で減速対象を判定(横位置に関係なく、ぶつかる横関係なら減速。1.8m以上離れていれば減速せず通過)。 全速追突消滅。十分離れた停車車は減速せず通過(過剰ブレーキなし)。
相手の急減速(brake-check)で0.63mまで接近。ICCが margin内(gap<3m)で「相手と同速」までしか減速せず、車間を開け直さない。 G2: 根号内を負まで許容 √(max(0, v_fwd²+2a(gap−margin))) → margin割れで相手より遅く=車間を開け直す。 brake-check時の最接近 0.63→1.35-1.5m。

3-2. 追い越し(いつ・どちらから・抜くか)

課題対処結果
追い越し側の左右迷い26回/走行。毎周期「今広い方」を選び直すためコミットできず、前方車の脇で足踏み→接近(dmin1.0m)→接触。成功5/15。 A: ①側スイッチにデッドバンド0.6m ②側コミットラッチ(通過完了or恒久失敗まで維持) ③拮抗時は次コーナーのアウト側を選択(前方25mの最大曲率の逆側。インが明確に広ければイン)。 左右反転26→8回、状態遷移30→5回。クリーン通過を確認。
同等速度の相手に蛇行して仕掛け続け、引き離される(e_y振れ6.98m、速度5.5km/hまで低下、車間15→54m)。コーナー先の「絶対抜けない位置」の相手にも仕掛ける。 速度差ゲート: 相手<6km/h(ペナルティ車)=障害物として即抜く(コーナー可) / closing>0.5m/sで追いつける相手のみ / コーナー中は「必要長≦残りコーナー長」で抜き切れる時のみ / 同等・速い相手は仕掛けない(追従)。 同等速度相手への蛇行消滅(全編クリーン追従)。相手10.8km/h→仕掛け、14.5km/h→追従、と適応動作を確認。
ICCで減速して追従に入ると closing=0になり「遅い相手を永久に抜けない」(現在速度基準の欠陥)。 C1: closingを「自分が出せる速度(v_pot=v_max)」基準に変更。 追従からの再仕掛けを確認。
停止車の3m後ろでデッドロック(ICCがmargin=3mでv=0 → 速度ゼロでは横移動を作れない → 7.8s/5.2s固まる)。 F3クリープ: 相手との実距離√(ds²+Δlat²)>1.8mの間は1.5m/sのクリープ前進を許し斜めに脱出。1.8m未満は完全停止(最後の防壁)。 デッドロック解消(以後のスタックは発進シーケンス7.8sのみ)。
駐車車に道を譲って停止(守りの横並び判定が相手速度を見ず、停止車を「並走車」と誤認→追い越し禁止→5.2s停止)。 G1: 守り発動は「走っている車(≥6km/h)」のみ。停止・低速車は「抜く相手」。 解消。

3-3. 守り(抜かれる側)と並走

課題対処結果
相手は最速35km/h・自車15km/h=抜かれる場面が多い。横に並ばれた時の振る舞いが未定義。 守りC: 横並び/後方から速い車を検知したら攻めのオフセット押し込みを抑制(相手の進路を邪魔しない)+相手は障害物として回避+壁近接(カート端-壁<0.5m)なら減速。 被追い越し時の押し込み動作なし。
真横(ds≈0)の車は誰も監視していない死角。コーナーで横間隔1.4-1.7mの並走が5秒継続(エッジ間5cm)。 並走ねばり: 自分側レーン幅(相手エッジ〜壁、先読み8m)が確保できる限り減速しない(ねばる)。lane<1.85mで相手より遅くして後退イールド、lane<1.45m(カート幅)で強減速。 並走50秒を平均12.8km/hで維持(ねばり)。誤イールドなし(lane発動値は全て≥2.33)。
ねばり実装のバグ: 横オフセット下限がなく「真正面の追従相手」にも発動→狭コーナーの縦列追従で誤って強減速する構造。 並走候補に dlat≥1.0m(実際に横に並んでいる)条件を追加。縦列はICCの管轄に分離。 狭コーナー縦列追従27サンプルで誤減速ゼロ(最低8.7km/h=相手なり)。

3-4. コード品質(一元化リファクタ)

課題対処結果
検知が4系統併存し帯も対象もバラバラ(analyzer=予測円・帯6.9m/context=帯3.9m/ACC=帯1.5m×2回呼び)。同じ相手に系統ごとに違う答え(d_min 1.0m vs 4m)を出し、デバッグ困難。予測円を「12台」と数える水増しも。 一元化: _scan_traffic()(唯一の他車スキャン=現在位置+平滑速度、帯はコリドー基準に統一) + _follow_speed_limit()(唯一のICC) + 判断ブロック1本。予測円は占有マップ(コリドー形状)専用に限定。死んだ変数・旧パラメータ(v_min/safe_clear/safe_brake等)を削除。 正味−134行、他車スキャン4回→1回/周期。G1/G2/C1/帯統一が構造として組込み。全過去問題ケースのリプレイ6/6で期待動作。バックアップ: mpc_controller.py.pre_unify.bak
